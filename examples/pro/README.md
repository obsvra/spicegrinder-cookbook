# Pro sample models

These extend the Free-tier showcases with **Perturb** (anomaly injection) and **Import** (sub-model decomposition / libraries). All require the **Pro** artifact.

| Free baseline | Pro extension | What it demonstrates |
|---------------|---------------|----------------------|
| `health/patient-vitals.xml` | `health/patient-vitals-perturbed.xml` | Timed clinical/sensor spikes via Perturb |
| | `health/patient-vitals-imported.xml` | Same + nominal physiology as Import library |
| | `health/vitals-nominal-lib.xml` | Reusable library fragment |
| `health/clinical-trial-arms.xml` | `health/clinical-trial-multi-site.xml` | **Parameterized sub-models**: one shared per-site library, `<Import>` 4x with different `<declare>` overrides — see [showcase-multi-site-trial.md](../docs/showcase-multi-site-trial.md) |
| | `health/site-arm-lib.xml` | Reusable, `<declare>`-parameterized library |

Also under `samples/pro/`: `person-model.xml`, `import-demo.xml`, `const-lib.xml` (earlier demos); `d6-lib.xml`/`dnd-ability-scores-import.xml` (bonus D&D sample's Import companion — see `samples/README.md`); `person-name-usa-female.xml`/`person-name-usa-male.xml` (real, frequency-weighted US full names — a simple `Append` of two `FlatFile(mode="weighted")` sources, no custom component, contrast with `person-model.xml`'s equal-weighted top-100 lists
+ `PersonAssembler`; see their own header comments for the SSA/Census data provenance);
+ `date-of-birth.xml` (business-object date generation via the new `Date` filter — `business.filters.Date`, `com.obsvra.spicegrinder.pro.datapoints.DateDataPoint` — a plain `Uniform` year `<input>` plus leap-year-correct day-of-year sampling and reproducible `minAge`/`asOf` age enforcement; see its own header comment);
+ `appointment-time.xml` (`business.filters.Time`/`TimeDataPoint` — `Date`'s exact sibling for time of day: a plain `Uniform` hour `<input>` plus uniform minute/second sampling within that hour, no leap-style landmine to guard against so no built-in constraint parameter is needed — "business hours only" falls out of the hour input's own range);
+ `address.xml` (`business.filters.Address`/`AddressDataPoint` — real city/state/zip from `city_state_zip.csv` (40,979 real USPS triples via GeoNames) plus a real street name from `street_names_weighted.csv` (the top 100 most common actual US street names, weighted by city count), street number and an optional unit generated internally; nominal-realism, not true realism — see its own header comment for the boundary being drawn);
+ `phone.xml` (`business.filters.Phone`/`PhoneDataPoint` — real area code from
`area_codes.csv` (389 real, in-service US NANP area codes via NANPA's own official database), exchange and subscriber number fully random NANP-valid by default — **not** restricted to the NANP-reserved fictional block, so a generated number can in principle reach a real live line though it carries zero connection to any real person or PII; see its own header comment for the full disclosure. Set `fictionalOnly="true"` on the `Phone` node to opt into the guaranteed-safe 555-01XX block instead — both modes are first-class, not just the default);
+ `email.xml`/`email-random.xml` (`business.filters.Email`/`EmailDataPoint` — closes out the personal-demographics arc. `email.xml` (default `nameBased=true`) derives the local part from a composed `PersonAssembler` name via one of 7 common real-world username patterns;
+ `email-random.xml` (`nameBased="false"`) instead uses a real, frequency-ranked common-word list (`email_words.txt`, 8,089 words) with no name input at all — "zookeeper32"-style. Domain always comes from `email_domains_weighted.csv` (real approximate global provider user-share percentages). Same collision-without-PII disclosure as `Phone`: a generated address can in principle coincide with a real, in-use inbox, but carries no tie to any real person's actual data either way — see either sample's header comment for the full writeup);
+ `creditcard.xml` (`business.filters.CreditCard`/`CreditCardDataPoint` — real network/BIN input from `creditcard_networks_weighted.csv` (Visa/Mastercard/American Express/Discover, weighted by real credit-card-only market share via WalletHub, each with a real BIN prefix and that network's standard length), remaining digits fully random and Luhn-valid by default — same collision-without-PII disclosure and same `fictionalOnly` opt-in shape as `Phone`: set `fictionalOnly="true"` on the `CreditCard` node to substitute the network's real, published test number (the exact numbers Stripe, and every other major payment processor, document for sandbox testing) instead of a randomly-filled one; see its own header comment for the full disclosure and data provenance);
+ `useragent.xml` (`business.filters.UserAgent`/`UserAgentDataPoint` — real browser/OS inputfrom `useragent_browser_os_weighted.csv` (StatCounter's own independently-published browser share and OS share, hand-combined nominally — not a jointly-measured distribution, see the CSV's own header comment), real-format UA strings assembled internally per browser/OS template with current major version numbers hardcoded in `UserAgent.java` so the reference table doesn't need updating on every browser release. No `fictionalOnly` toggle — a UA string carries no PII-collision concern, unlike `Phone`/`CreditCard`; see its own header comment for the full disclosure and data provenance);
+ `ipaddress.xml` (`business.generators.IPAddress`/`IPAddressDataPoint` — real public-unicast IPv4 space by default, with real IANA special-purpose blocks (private/loopback/link-local/multicast/reserved/etc.) excluded so the result looks like a real routable address. No composed input needed — the first business object built as a generator rather than a filter. Same collision-without-PII disclosure and same `fictionalOnly` toggle shape as `Phone`: set `fictionalOnly="true"` to restrict every draw to the three real RFC 5737 TEST-NET blocks instead, guaranteed by the standard itself to never be publicly routable; see its own header comment for the full disclosure);
+ `ssn.xml` (`business.generators.SSN`/`SSNDataPoint` — real US Social Security Number format, area from the real historically-allocatable [001,899] range (excluding 666) by default, no composed input needed. Same collision-without-PII disclosure and same `fictionalOnly` toggle shape as `Phone`/`IPAddress`: set `fictionalOnly="true"` to restrict area to the SSA's own published never-allocated [900,999] range instead; see its own header comment for the full disclosure);
+ `npi.xml` (`business.generators.NPI`/`NPIDataPoint` — real US National Provider Identifier format per the CMS NPI Final Rule, first digit 1 (individual) or 2 (organization) — random by default, or fixed via `type=`. Check digit is a real Luhn checksum computed over the 9-digit base prefixed with the constant `80840`, the ISO/IEC 7812 health-industry issuer identifier CMS's own rule specifies. Same collision-without-PII disclosure as `Phone`/`SSN`, but no `fictionalOnly` toggle: CMS/NPPES publishes no reserved-safe NPI block; see its own header comment for the full disclosure);
+ `vin.xml` (`business.filters.VIN`/`VINDataPoint` — real WMI (World Manufacturer Identifier) input from `vin_manufacturers.csv` (15 real codes assigned by SAE International, cross-checked against NHTSA's own public vPIC database), remaining 14 characters generated internally per the real NHTSA/ISO 3779 VIN standard including a correct check digit (position 9) and a real model-year code (position 10). Same collision-without-PII disclosure as `Phone`, but no `fictionalOnly` toggle: no standards body publishes a reserved-safe VIN block; see its own header comment for the full disclosure);
+ `company-name.xml` (`business.filters.CompanyName`/`CompanyNameDataPoint` — two real words (from the same `email_words.txt` list `Email`'s random-word mode uses) joined with a space or "&" plus a real, standard US legal-entity suffix from `business_suffixes.csv` (deliberately unweighted — no citable per-suffix relative-frequency figure found, same honesty standard as `vin_manufacturers.csv`). No `fictionalOnly` toggle: a company name is not sensitive PII; see its own header comment for the full disclosure); `business-day.xml` (`business.filters.BusinessDay` — `Date`'s calendar/holiday-aware sibling: same leap-year-correct day-of-year draw, redrawn until the result is a real US federal business day (Monday-Friday, excluding all 11 real holidays under 5 U.S.C. § 6103, including the real weekend-observance shift). Reuses `DateDataPoint` directly. No `fictionalOnly` toggle: a calendar date carries no PII-collision concern; see its own header comment for the full holiday list and computation);
+ `iban.xml` (`business.filters.IBAN`/`IBANDataPoint` — real per-country BBAN structure (ISO 13616) for 6 countries from `iban_countries.csv`, plus a real, correctly computed ISO 7064 MOD-97 checksum. Nominal realism, not true realism: several countries' own internal BBAN check algorithms (France's RIB key, Spain's, Italy's CIN, the Netherlands' "elfproef") are not also implemented — only the universal, required MOD-97 check is guaranteed correct. No `fictionalOnly` toggle: no standards body publishes a reserved-safe IBAN block; see its own header comment for the full disclosure and per-country field breakdown);
+ `ein.xml` (`business.generators.EIN`/`EINDataPoint` — real US Employer Identification Number format, prefix drawn from the real 83 currently-assignable IRS prefixes (all of 01-99 excluding the IRS's own documented invalid-prefix list), no composed input needed. Same collision-without-PII disclosure as `Phone`/`SSN`, but no `fictionalOnly` toggle: the IRS publishes no reserved-safe-for-testing block; see its own header comment for the full disclosure);
+ `imei.xml` (`business.generators.IMEI`/`IMEIDataPoint` — real 15-digit mobile device IMEI format, TAC (8 digits) and serial (6 digits) drawn uniformly at random, 15th digit a real Luhn check digit over the preceding 14, no composed input needed. TAC/serial are not sourced from a real per-device GSMA allocation table — a confidently-verified curated subset of those exact mappings wasn't available to cite directly; only the real format and real check digit are guaranteed correct, disclosed explicitly in its own header comment. No `fictionalOnly` toggle: GSMA publishes no reserved-safe-for-testing block);
+ `macaddress.xml` (`business.filters.MACAddress`/`MACAddressDataPoint` — real 6-byte MAC address, a real IEEE-assigned vendor OUI composed input drawn from 15 curated real vendors in `mac_vendors.csv`, remaining 3 NIC-specific bytes drawn uniformly at random, rendered as the standard colon-separated uppercase hex form. Same composed-input shape as `VIN`. No `fictionalOnly` toggle: IEEE 802's "locally administered" address space is real but actively used by real software for its own addresses, not an officially reserved never-collide block; see its own header comment for the full disclosure);
+ `isbn.xml` (`business.filters.ISBN`/`ISBNDataPoint` — real 13-digit ISBN, a real single-digit ISBN registration-group composed input (0/1 English, 2 French, 3 German, 4 Japan, 5 former USSR, 7 China) from `isbn_registration_groups.csv`, fixed real "978" EAN Bookland prefix, remaining 8 publisher+title digits drawn uniformly at random, real ISO 2108/EAN-13 check digit. Same composed-input shape as `VIN`/`MACAddress`. No `fictionalOnly` toggle: no standards body publishes a reserved-safe ISBN block; see its own header comment for the full disclosure);
+ `domain-name.xml` (`business.filters.DomainName`/`DomainNameDataPoint` — a real word from the shared `email_words.txt` list (also used by `Email`/`CompanyName`) joined with a real, currently-significant TLD from `domain_tlds.csv` (10 curated real TLDs, unweighted — see that CSV's own header comment for why), e.g. `pursuit.io`. No `fictionalOnly` toggle: a domain name is not sensitive PII, and there is no reserved-safe registry to opt into even if one were wanted);
+ `ipv6address.xml` (`business.generators.IPv6Address`/`IPv6AddressDataPoint` — real public unicast IPv6 space by default, excluding the real IANA IPv6 Special-Purpose Address Registry blocks (fetched directly from IANA's own published registry text). `fictionalOnly` restricts to the real RFC 3849 documentation prefix `2001:0db8::/32`. Rendered in the full, uncompressed 8-group form; no RFC 5952 zero-compression applied, disclosed explicitly. Same collision-without-PII and restricted-range-toggle shape as `IPAddress`; see its own header comment for the full disclosure).

## Run (Pro JAR / `-Ppro` classpath)

Analyze (static complexity + throughput):

```bash
java -cp target/spicegrinder-*-pro.jar com.obsvra.spicegrinder.tools.ModelAnalyzerApp \
  samples/pro/health/patient-vitals-perturbed.xml
```

Or draw observations directly:

```bash
java -cp target/spicegrinder-*-pro.jar com.obsvra.spicegrinder.tools.Grind --count 5 \
  samples/pro/health/patient-vitals-perturbed.xml
```

Load + draw via your harness or GUI using the Pro artifact only.
